# Smarttour-Assistant 测试用例

说明：本文档基于项目真实接口、页面与数据编写。用例编号规则 TC-<模块>-<序号>。优先级 P0=致命、P1=严重、P2=一般、P3=轻微。
后端基址 http://localhost:8080，前端基址 http://localhost:5174。

通用测试账号：
- 管理员：admin / 123456（另有 admin1、admin2、admin3，密码同）
- 普通用户：testfav_a / 123456（另有 张三、麻子，密码同）
- 管理员注册码：admin2026

## 一、用户模块（TC-USER）

### TC-USER-001 普通用户登录成功
- 优先级：P0
- 前置条件：后端已启动；testfav_a 账号存在且 status 正常。
- 测试步骤：
  1. 打开 http://localhost:5174/login，登录模式。
  2. 输入用户名 testfav_a、密码 123456，点登录。
- 预期结果：登录成功跳转首页 /；localStorage 写入 token 与 userInfo；页面顶部显示用户名与头像。

### TC-USER-002 管理员登录成功
- 优先级：P0
- 前置条件：admin 账号存在，role=1。
- 测试步骤：登录页输入 admin / 123456 并登录。
- 预期结果：自动跳转 /admin/dashboard，进入管理员独立后台（侧边栏 + 5 个 Tab）。

### TC-USER-003 错误密码登录失败
- 优先级：P1
- 测试步骤：输入 testfav_a / 错误密码，点登录。
- 预期结果：toast 提示用户名或密码错误；不跳转；不写入 token。

### TC-USER-004 未登录访问受保护页面
- 优先级：P1
- 测试步骤：清空 localStorage 后直接访问 /、/community、/profile、/admin。
- 预期结果：全部重定向到 /login（访问 /admin 跳登录并带 redirect 参数）。

### TC-USER-005 普通用户注册成功
- 优先级：P1
- 测试步骤：
  1. 登录页切到注册模式，用户类型选「普通用户」。
  2. 填用户名（如 testuser_0903）、密码、确认密码一致，点注册。
- 预期结果：注册成功并自动登录跳转 /；数据库 user 表新增记录 role=0。

### TC-USER-006 两次密码不一致注册失败
- 优先级：P2
- 测试步骤：注册时密码与确认密码输入不同。
- 预期结果：前端拦截提示两次密码不一致，不发请求。

### TC-USER-007 管理员注册码正确
- 优先级：P1
- 测试步骤：注册模式选「管理员」，填写资料 + 注册码 admin2026，提交。
- 预期结果：注册成功，新账号 role=1，登录后进入 /admin。

### TC-USER-008 管理员注册码错误
- 优先级：P1
- 测试步骤：注册模式选「管理员」，注册码填 wrongcode，提交。
- 预期结果：后端返回业务码 400，提示注册码错误；user 表不新增管理员记录。

### TC-USER-009 用户名重复注册
- 优先级：P2
- 测试步骤：用已存在的用户名 testfav_a 再次注册。
- 预期结果：提示用户名已存在，注册失败。

### TC-USER-010 修改密码
- 优先级：P2
- 前置条件：已登录普通用户。
- 测试步骤：个人中心进入修改密码，输旧密码 123456、新密码（如 123456），提交；退出后用新密码登录。
- 预期结果：提示修改成功；新密码可登录；旧密码登录失败。（测试后请改回原密码）

### TC-USER-011 修改资料（头像上传）
- 优先级：P1
- 测试步骤：个人中心点头像，选择本地图片上传。
- 预期结果：上传成功后首页欢迎栏、个人中心、社区帖子头像同步更新；文件存入 D:/Front-end-learning/project/Smarttour_Assistant/uploads；user.avatar 写入访问 URL。

### TC-USER-012 JWT 过期自动跳登录
- 优先级：P2
- 测试步骤：登录后手动将 localStorage 的 token 改为乱码，刷新页面或触发任意接口。
- 预期结果：request.js 拦截器检测到 401 / JWT 过期关键词，清除 token 并跳转 /login。

## 二、AI 模块（TC-AI）

### TC-AI-001 行程规划成功
- 优先级：P1
- 前置条件：已登录普通用户；application.yml 中 llm.api-key 有效。
- 测试步骤：
  1. 首页规划卡片选起始地成都、目的地九寨沟，预算 3000，出发日期选今天+3、返回日期选今天+5（共 3 天）。
  2. 点「开始AI规划」。
- 预期结果：跳转 /detail 展示 AI 生成的行程方案；等待不超过 120 秒；无报错。

### TC-AI-002 规划缺少必填项拦截
- 优先级：P2
- 测试步骤：不选目的地直接点「开始AI规划」；预算填 50 再点；不选日期点；选同一天（1 天）点。
- 预期结果：分别提示「请选择目的地」「请输入大于等于100的预算」「请选择出发和返回日期」「行程至少需要2天」。

### TC-AI-003 AI 流式对话
- 优先级：P2
- 前置条件：已登录。
- 测试步骤：底部 Tab 进入 AI 助手，输入「推荐九寨沟三天玩法」发送。
- 预期结果：回复逐字流式渲染（ChatBubble 持续增长），不是一次性返回；结束后无 loading 卡死。

## 四、购物车与订单模块（TC-CART）

### TC-CART-001 未登录加购拦截
- 优先级：P0
- 测试步骤：未登录状态点商品购物车图标。
- 预期结果：提示「请先登录」并跳转 /login。

### TC-CART-002 未选日期加购拦截
- 优先级：P0
- 前置条件：已登录。
- 测试步骤：规划卡片不选出发/返回日期，直接点商品购物车图标。
- 预期结果：toast「请先在规划卡片选择出发日期和返回日期」；Network 中无 /api/cart/add 请求。（该项已实测通过）

### TC-CART-003 起始地不匹配拦截
- 优先级：P1
- 测试步骤：规划卡片起始地选「北京」，目的地选九寨沟，选好日期；对 origin=成都 的商品点加购。
- 预期结果：toast「起始地不匹配！产品起始地：成都」；不发请求。

### TC-CART-004 目的地不匹配拦截
- 优先级：P1
- 测试步骤：起始地成都、目的地选「北京」，选好日期；对 destination 为九寨沟的商品点加购。
- 预期结果：toast「目的地不匹配！产品目的地：四川省 九寨沟」；不发请求。

### TC-CART-005 天数不匹配拦截（严格相等）
- 优先级：P1
- 测试步骤：起始地成都、目的地九寨沟，出发今天+3、返回今天+8（共 6 天）；对 duration 为「3天2晚」的商品点加购。
- 预期结果：toast「天数不匹配！产品行程：3天2晚（3天），您选了6天」；不发请求。

### TC-CART-006 全部匹配加购成功
- 优先级：P0
- 测试步骤：起始地成都、目的地九寨沟、出发今天+3 返回今天+5（3 天）；打开九寨沟 3 天商品详情，点「加入购物车」。
- 预期结果：toast「已加入购物车 🛒」；Network 中 POST /api/cart/add 请求 body 含 productId、quantity:1、startDate、endDate；响应 code=200；数据库 cart_order 新增记录且 start_date/end_date 与所选一致。

### TC-CART-007 同商品同日期重复加购合并数量
- 优先级：P2
- 前置条件：TC-CART-006 已成功。
- 测试步骤：保持相同日期，对同一商品再次点加购。
- 预期结果：响应 type=inc，购物车中该记录 quantity=2，而不是新增第二条记录。

### TC-CART-008 同商品不同日期生成独立购物车项
- 优先级：P2
- 测试步骤：改选出发今天+10、返回今天+12（3 天），对同一商品加购。
- 预期结果：cart_order 新增一条独立记录（start_date 不同），与原记录并存。

### TC-CART-009 缺少日期参数后端拒绝
- 优先级：P1
- 测试步骤（接口）：带 token POST /api/cart/add，body 只传 {"productId":1,"quantity":1}，不传 startDate/endDate。
- 预期结果：返回业务码 400，提示「请选择出发日期和返回日期」；数据库不新增记录。

### TC-CART-010 购物车/订单列表
- 优先级：P1
- 测试步骤：个人中心打开「我的订单」，切换「购物车」「已支付」Tab。
- 预期结果：购物车 Tab 展示 status=0 记录（含出行日期、标题快照、价格）；已支付 Tab 展示 status=1 记录；接口 GET /api/cart/my?status=0 / status=1 数据一致。

### TC-CART-011 删除购物车记录
- 优先级：P2
- 测试步骤：购物车中删除一条记录。
- 预期结果：记录消失；接口 POST /api/cart/delete 返回成功；数据库该记录删除；删除他人记录 id 不生效（DELETE 带 user_id 条件）。

### TC-CART-012 单条支付
- 优先级：P1
- 测试步骤：购物车中点一条记录的支付。
- 预期结果：status 由 0 变 1，paid_time 写入；商品 sold_count 增加；该记录移到「已支付」Tab。

### TC-CART-013 一键支付
- 优先级：P2
- 测试步骤：购物车中有多条记录时点「一键支付」。
- 预期结果：全部 status=0 记录变为 1；返回支付笔数与总金额；空购物车点支付提示「购物车是空的」。

## 七、前端非功能与兼容性（TC-FE）

### TC-FE-001 移动端布局适配
- 优先级：P2
- 测试步骤：Chrome DevTools 切手机模拟（iPhone SE 375×667、iPhone 14 Pro 393×852），逐页浏览首页/社区/个人中心/登录/管理后台。
- 预期结果：无横向滚动；卡片、弹窗、Tabbar 布局正常；底部 Tabbar z-index 正确不被遮挡。

### TC-FE-002 图片加载兜底
- 优先级：P3
- 测试步骤：将某商品图片 URL 改为无效地址刷新。
- 预期结果：触发 onError 回退默认图，不出现破损图标。

### TC-FE-003 控制台无错误
- 优先级：P2
- 测试步骤：完整走一遍登录→规划→查询→加购→支付→社区发布→后台各 Tab，全程开 F12 Console。
- 预期结果：无红色错误；无 Unsplash/ORB 报错；无 van-field NaN 警告；无 Vue warn。

### TC-FE-004 手机真机局域网访问
- 优先级：P2
- 前置条件：vite.config.js 设 host:'0.0.0.0'；防火墙放行 5174/8080；手机与 PC 同 WiFi。
- 测试步骤：ipconfig 查 PC 局域网 IP（如 192.168.x.x），手机浏览器访问 http://<PC-IP>:5174。
- 预期结果：手机正常打开页面，登录、加购等接口请求正常（经 Vite proxy 转发 8080）。

### TC-FE-005 文件上传大小限制
- 优先级：P3
- 测试步骤：上传一张超过 10MB 的图片作为头像。

## 附：接口快速冒烟清单（PowerShell）

```powershell
# 1. 普通用户登录
$login = Invoke-RestMethod -Uri 'http://localhost:8080/api/user/login' -Method Post -ContentType 'application/json' -Body '{"username":"testfav_a","password":"123456"}'
$token = $login.data.token

# 2. 商品公开列表（无需 token）
Invoke-RestMethod -Uri 'http://localhost:8080/api/product/list'

# 3. 动态查询
Invoke-RestMethod -Uri 'http://localhost:8080/api/product/search?origin=成都&destination=九寨沟&budget=5000&duration=3'

# 4. 带日期加购
Invoke-RestMethod -Uri 'http://localhost:8080/api/cart/add' -Method Post -ContentType 'application/json' -Headers @{Authorization="Bearer $token"} -Body '{"productId":1,"quantity":1,"startDate":"2026-09-05","endDate":"2026-09-07"}'

# 5. 查购物车
Invoke-RestMethod -Uri 'http://localhost:8080/api/cart/my?status=0' -Headers @{Authorization="Bearer $token"}

# 6. 管理员接口越权验证（普通 token 应被拒）
try { Invoke-RestMethod -Uri 'http://localhost:8080/api/admin/users' -Headers @{Authorization="Bearer $token"} } catch { $_.Exception.Response.StatusCode.value__ }
```
