# Smarttour-Assistant 测试计划

## 1. 项目概述

Smarttour-Assistant 是一款 AI 智能旅行助手 Web 应用，采用前后端分离架构：

- 后端：Spring Boot 4.1 + MyBatis 3.0 + MySQL 8.0（travel 库），运行于 http://localhost:8080
- 前端：Vue 3 + Vite + Vant 4（移动端组件库）+ ECharts 6，运行于 http://localhost:5174
- 外部依赖：SiliconFlow 大模型 API（AI 行程规划 / 流式对话）

系统包含两类角色：普通用户（role=0）与管理员（role=1），两端路由与接口均做权限隔离。

## 2. 测试目标

1. 验证全部业务功能符合需求（用户、AI 规划、商品、购物车订单、社区、管理员后台六大模块）。
2. 验证权限隔离：普通用户无法访问管理员接口/页面，管理员不进入用户端。
3. 验证数据隔离：用户数据（收藏、点赞、订单、分享）严格按 user_id 隔离，不能越权操作他人数据。
4. 验证关键边界条件：加购 5 重校验、JWT 过期处理、文件上传限制、并发点赞唯一性。
5. 验证移动端 UI 适配（Vant 组件在手机分辨率下布局正常）。

## 3. 测试范围

### 3.1 纳入测试范围

- 用户模块：注册（含管理员注册码）、登录、资料修改、密码修改、头像上传、反馈。
- AI 模块：行程推荐（同步）、AI 流式对话（SSE/chunk）。
- 商品模块：商品列表、详情、动态条件查询（起始地/目的地/预算/天数）。
- 购物车订单模块：加入购物车（含出行日期 + 5 重校验）、购物车/订单列表、删除、单条支付、一键支付、同商品同日期合并数量。
- 社区模块：发布分享、点赞（复合主键防重复）、评论、收藏（唯一约束防重复）、我的收藏/我的分享。
- 管理员模块：仪表盘统计、用户管理（角色切换/启停）、商品管理（增删改）、订单管理（状态/删除）、数据可视化（ECharts 4 图表）。
- 前端非功能：路由守卫、JWT 过期自动跳登录、图片加载兜底、响应式布局。

### 3.2 不纳入测试范围

- 大模型 API 自身的回答质量（第三方服务，只验证接口连通与流式渲染）。
- 支付金额的真实扣款（系统内为状态模拟，无真实支付网关）。
- 高并发压力测试（课程/毕设项目，以功能测试为主）。
- iOS/Android 原生安装包（当前为 H5 形态）。

## 4. 测试策略

| 测试类型 | 占比 | 工具/方法 | 说明 |
|---|---|---|---|
| 单元测试 | 20% | JUnit 5（Maven test） | 后端工具类/纯逻辑，如 JwtUtils 签发解析、天数计算等不依赖 DB 的逻辑 |
| 接口集成测试 | 35% | @SpringBootTest + MockMvc / PowerShell Invoke-RestMethod | 真实 Spring 上下文 + 真实 MySQL，@Transactional 自动回滚防脏数据 |
| 功能测试（手工 E2E） | 35% | 浏览器手工 + F12 Network/Console | 按《测试用例.md》逐用例执行，覆盖前端校验与交互 |
| 兼容性/UI 测试 | 10% | Chrome DevTools 手机模拟（375×667 等） | Vant 移动端布局、弹窗、Tabbar |

测试分层原则：前端校验（如加购 5 重校验 toast）用浏览器手工验证；后端规则（如注册码校验、日期落库、数据隔离）用接口测试验证；纯逻辑用单元测试。

## 7. 风险与对策

1. 大模型 API 响应慢或不可用：AI 用例超时阈值设为 120s；API 故障时跳过 AI 用例并在报告中标注阻塞，不阻塞其他模块。
2. 集成测试污染数据库：集成测试类加 @Transactional，方法结束自动回滚；手工测试产生的购物车数据可直接删除或用测试账号。
3. 浏览器缓存导致旧代码：每轮测试前 Ctrl+Shift+R 硬刷新；Vite 依赖缓存异常时重启 dev server。
4. 手机端无法访问：确认 vite.config.js 的 host 为 0.0.0.0、Windows 防火墙放行 5174/8080、手机与 PC 同网段，用 PC 局域网 IP 访问。
5. JWT 24 小时过期导致用例中途失效：批量执行接口测试前重新登录获取新 token。

## 8. 准入与准出标准

- 准入：后端 mvnw compile 通过、前端 npm run dev 无报错、MySQL 中 7 张表齐全、测试账号可登录。
- 准出：测试用例 100% 执行；致命/严重缺陷 0 遗留；一般缺陷有记录且不影响主流程；测试报告签署完成。

## 9. 缺陷分级

- 致命（P0）：无法登录/注册、后端无法启动、数据越权、支付丢单。
- 严重（P1）：核心功能不可用（加购失败、社区不显示、管理员无法管理）。
- 一般（P2）：非核心功能异常、提示文案错误、边界条件未拦截。
- 轻微（P3）：样式错位、错别字、控制台警告。
